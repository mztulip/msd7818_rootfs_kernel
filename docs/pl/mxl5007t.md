# Tuner MxL5007T: obsługa przez I2C krok po kroku

Tuner MaxLinear **MxL5007T v4** siedzi na sprzętowym I2C portu 0 (pinmux wariant 1) pod adresem **`0x60`** (8-bit: `0xC0` zapis, `0xC1` odczyt). To jedyne urządzenie na tej magistrali (skan `0x08`–`0x77` przez `devmem`, 2026-10-13). Opis kontrolera I2C: [i2c.md](i2c.md).

Źródła wiedzy o rejestrach: sterownik Linuksa `linux_msd781x/drivers/media/tuners/mxl5007t.c` (M. Krufky) oraz `MxL5007T_tune_radio.pdf`. Publicznej dokumentacji MxL5007T nie ma.

Oznaczenia: ✅ sprawdzone na płycie, 🔍 z kodu sterownika, ❓ niesprawdzone.

## Protokół MxL5007T

| Operacja | Ramki I2C |
|---|---|
| zapis rejestru | `S C0 reg val P` |
| odczyt rejestru | `S C0 FB reg` + `Sr C1 [dane+NACK] P` (`0xFB` = „przygotuj rejestr do odczytu”) ✅ |
| miękki reset | `S C0 FF P` 🔍 |

Rejestry tylko do odczytu, które warto znać:
- `0xD9` = ID układu: `0x14` = v4 ✅ (`0x11`/`0x12` v1, `0x21`–`0x24` v2.x),
- `0xD8` = stan PLL: bity `[3:2]` = `11` → syntezer RF zablokowany, bity `[1:0]` = `11` → referencja zablokowana. ✅ Po włączeniu zasilania `0x03` (tylko referencja), po strojeniu `0x0F`.

## Sposób A: same `devmem` (bez sterownika I2C)

Działa na każdym kernelu. Wpisz w powłoce płyty (Linux, adresy fizyczne `0x1F……`):

```sh
# --- przygotowanie (raz po starcie) ---
devmem 0x1F203C24 16 0x0001                    # pinmux: I2C port 0, wariant 1
devmem 0x1F206800 8 1; devmem 0x1F206800 8 0   # reset kontrolera
devmem 0x1F206838 8 0x41                       # S1CON: ENS1 + zegar CR=1

# --- funkcje pomocnicze ---
C=0x1F206838; D=0x1F206834; S=0x1F206839
i2c_st()   { devmem $S 8; }                               # S1STA
i2c_start(){ devmem $C 8 0x65; }                          # START / powtórzony START
i2c_tx()   { devmem $D 8 $1; devmem $C 8 0x45; }          # wyślij bajt (adres albo dane)
i2c_rxn()  { devmem $C 8 0x41; devmem $D 8; }             # odbierz bajt z NACK (ostatni)
i2c_stop() { devmem $C 8 0x55; }

mxl_w() {  # mxl_w REG VAL
  i2c_start; i2c_tx 0xC0; i2c_tx $1; i2c_tx $2; i2c_stop
}
mxl_r() {  # mxl_r REG  -> wypisuje wartość
  i2c_start; i2c_tx 0xC0; i2c_tx 0xFB; i2c_tx $1
  i2c_start; i2c_tx 0xC1; i2c_rxn; i2c_stop
}
```

Każdy krok można też wykonać ręcznie i po nim sprawdzić `i2c_st`:

| Krok | Polecenie | Oczekiwany S1STA |
|---|---|---|
| START | `i2c_start` | `0x08` |
| adres + zapis | `i2c_tx 0xC0` | `0x18` (ACK) |
| bajt danych | `i2c_tx 0xFB` | `0x28` (ACK) |
| powtórzony START | `i2c_start` | `0x10` |
| adres + odczyt | `i2c_tx 0xC1` | `0x40` (ACK) |
| odbiór ostatniego bajtu | `i2c_rxn` | `0x58` (+ wypisuje bajt) |
| STOP | `i2c_stop` | `0xF8` |

Przykład ✅:
```sh
mxl_r 0xD9        # -> 0x14  (MxL5007T v4)
```

## Sposób B: sterownik `i2c-mstar-miic` + `i2c-tools`

Z kernelem zbudowanym z `CONFIG_I2C_MSTAR_MIIC=y` i DTS, w którym `&miic0` ma `mstar,chiptop`/`mstar,port`/`mstar,pad-mode` (patrz [i2c.md](i2c.md)), magistrala pojawia się jako `/dev/i2c-0`, a pinmux ustawia sterownik.

```sh
i2cdetect -l                                   # lista magistral
i2cdetect -y 0                                 # skan; powinno być tylko 60
i2ctransfer -y 0 w2@0x60 0xfb 0xd9 r1@0x60     # ID -> 0x14
i2ctransfer -y 0 w2@0x60 0x01 0x01             # zapis: rejestr 0x01 = 0x01
```

W dalszych przykładach `mxl_w`/`mxl_r` można zastąpić:
```sh
mxl_w() { i2ctransfer -y 0 w2@0x60 $1 $2; }
mxl_r() { i2ctransfer -y 0 w2@0x60 0xfb $1 r1@0x60; }
```

## Przykład: inicjalizacja i strojenie (wg `mxl5007t.c`, ✅ sprawdzone 2026-10-13 przez `i2ctransfer`)

Parametry płyty, które trzeba założyć ❓:
- **kwarc tunera: 24 MHz** (domyślne wartości `init_tab` w sterowniku: `0x03` = `0x48`, `0x05` = `0x04`),
- **IF: 4,57 MHz** (typowe dla DVB-T 8 MHz; nazwa `schematics/dodatkory_tor_posredniej4.5Mhz.png` sugeruje ok. 4,5 MHz),
- wyjście zegara tunera **zostawione włączone** (bit 3 w `0x03`), bo może taktować inne układy na płycie.

### 1. Reset i inicjalizacja (tryb DVB-T)

```sh
i2c_start; i2c_tx 0xC0; i2c_tx 0xFF; i2c_stop   # miękki reset (w sposobie B: i2ctransfer -y 0 w1@0x60 0xff)

mxl_w 0x02 0x03   # IF: [3:0]=3 -> 4,57 MHz, [4]=0 IF nieodwrócone
mxl_w 0x03 0x48   # [7:4]=4 -> kwarc 24 MHz, [3]=1 wyjście zegara, [2:0]=0 amplituda
mxl_w 0x05 0x04   # [3:0]=4 -> referencja 24 MHz
mxl_w 0x06 0x11   # [4:0]=0x11 -> tryb DVB-T (0x10 ISDB-T, 0x12 ATSC)
mxl_w 0x2e 0x15; mxl_w 0x30 0x10; mxl_w 0x45 0x58; mxl_w 0x48 0x19
mxl_w 0x52 0x03; mxl_w 0x53 0x44; mxl_w 0x6a 0x4b; mxl_w 0x76 0x00
mxl_w 0x78 0x18; mxl_w 0x7a 0x17; mxl_w 0x85 0x06
mxl_w 0x01 0x01   # TOP_MASTER_ENABLE (wybudzenie)
```

Kody IF dla rejestru `0x02` `[3:0]`: `0` = 4 MHz, `2` = 4,5, `3` = 4,57, `4` = 5, `5` = 5,38, `6` = 6, `7` = 6,28, `8` = 9,1915, `9` = 35,25, `A` = 36,15, `B` = 44 MHz.

### 2. Strojenie na częstotliwość

Częstotliwość RF zapisuje się jako 16-bitowa liczba stałoprzecinkowa: 10 bitów MHz + 6 bitów ułamka (krok 15,625 kHz):
```
N = round_down(f_MHz × 64)   (+1, jeśli reszta > 7,8125 kHz)
reg 0x0D = N & 0xFF,  reg 0x0E = N >> 8
```

Szerokość pasma, rejestr `0x0C`: `0x15` = 6 MHz, `0x2A` = 7 MHz, `0x3F` = 8 MHz.
Rejestr `0x80`: `0x01`, a dla f ≥ 333 MHz `0x41`.

**Przykład: 474 MHz (kanał UHF 21), 8 MHz.** N = 474 × 64 = 30336 = `0x7680`:
```sh
mxl_w 0x0f 0x00   # przerwij strojenie
mxl_w 0x0c 0x3f   # pasmo 8 MHz
mxl_w 0x0d 0x80   # N, młodszy bajt
mxl_w 0x0e 0x76   # N, starszy bajt
mxl_w 0x1f 0x87; mxl_w 0x20 0x1f; mxl_w 0x21 0x87; mxl_w 0x22 0x1f
mxl_w 0x80 0x41   # f >= 333 MHz
mxl_w 0x0f 0x01   # start strojenia
sleep 1
mxl_r 0xD8        # 0x0F = RF i referencja zablokowane   ✅ wynik: 0x0F
```

**Przykład: 100 MHz (pasmo FM, jak w `MxL5007T_tune_radio.pdf`), 6 MHz.** N = 6400 = `0x1900`:
```sh
mxl_w 0x0f 0x00; mxl_w 0x0c 0x15; mxl_w 0x0d 0x00; mxl_w 0x0e 0x19
mxl_w 0x1f 0x87; mxl_w 0x20 0x1f; mxl_w 0x21 0x87; mxl_w 0x22 0x1f
mxl_w 0x80 0x01; mxl_w 0x0f 0x01
sleep 1; mxl_r 0xD8   # ✅ wynik: 0x0F
```

Przelicznik dla dowolnej częstotliwości (na płycie, busybox `sh`):
```sh
f_khz=474000
n=$(( f_khz * 64 / 1000 )); r=$(( f_khz * 64 % 1000 )); [ $r -gt 500 ] && n=$((n+1))
printf "0x0d=0x%02X 0x0e=0x%02X\n" $((n & 255)) $((n >> 8))
```
(zaokrąglenie przybliża regułę sterownika: +1, gdy reszta > 7,8 kHz, czyli pół kroku).

### 3. Uśpienie

```sh
mxl_w 0x01 0x00   # standby
mxl_w 0x0f 0x00
```

## Uwagi

- Wbudowany demodulator DVB-T Kronusa nie jest jeszcze obsługiwany w Linuksie, więc strojenie samo w sobie nie daje obrazu. Przydaje się do testów: blokada PLL w `0xD8`, a sygnał IF jest widoczny oscyloskopem na wyjściu IF tunera.
- Przy ustawieniu kwarcu 24 MHz referencja i RF się blokują (`0xD8` = `0x0F`), co jest zgodne z kwarcem 24 MHz, ale go nie dowodzi (blokada była też przed inicjalizacją). Częstotliwość IF (4,57 MHz) nie jest potwierdzona; wymagałoby to pomiaru na wyjściu IF.
- Prędkość magistrali dla bitów zegara `CR=1` nie była mierzona. Tuner odpowiada poprawnie.

## Sterownik `mxl5007t` w kernelu Linuksa

Kod jest w drzewie: `linux_msd781x/drivers/media/tuners/mxl5007t.c` (+ `mxl5007t.h`). **Nie da się go jednak użyć samodzielnie** (stan 2026-10-13):

- **Nie jest włączony.** W `.config` jest `# CONFIG_MEDIA_DIGITAL_TV_SUPPORT is not set`, więc rdzeń DVB i `CONFIG_MEDIA_TUNER_MXL5007T` się nie kompilują.
- **To nie jest zwykły sterownik I2C.** Nie ma `i2c_driver` ani `of_match_table`, więc węzeł `tuner@60` w DTS niczego nie podepnie. To element podsystemu DVB: wywołuje go sterownik demodulatora albo mostka przez `dvb_attach(mxl5007t_attach, fe, i2c_adap, 0x60, &cfg)`. Przykłady takich sterowników: `drivers/media/usb/dvb-usb-v2/af9035.c`, `af9015.c`, `drivers/media/usb/dvb-usb/dib0700_devices.c`, `drivers/media/usb/au0828/au0828-dvb.c`. Tuner dostaje wtedy operacje frontendu: `set_params` (strojenie), `init`/`sleep`, `get_if_frequency`.
- **Brakuje sterownika demodulatora Kronusa** (wbudowany DVB-T, 8051 + DSP, patrz [demodulator_if.md](demodulator_if.md)). Bez niego nie powstanie `/dev/dvb/adapter0/frontend0`, a sam tuner nie zrobi nic ponad to, co dają `i2ctransfer`/`devmem` opisane wyżej.

### Możliwe drogi

| Droga | Co daje | Trudność |
|---|---|---|
| `i2ctransfer` / skrypt (ten dokument) | strojenie, odczyt stanu PLL | gotowe ✅ |
| Moduł-„klej”: atrapa frontendu DVB + `mxl5007t_attach` na `/dev/i2c-0` | strojenie przez standardowe API DVB, bez demodulacji i bez obrazu | średnia, w praktyce niewiele więcej niż skrypt |
| Sterownik frontendu DVB dla demodulatora Kronusa (ładowanie firmware'u 8051, skrzynka pocztowa, AGC, wyjście TS) + `mxl5007t_attach` | prawdziwy odbiór DVB-T (`dvbv5-scan`, `dvbv5-zap`); obraz dopiero z demuxem TSP i dekoderem | wysoka |

Konfiguracja tunera dla `mxl5007t_attach` na tej płycie (`struct mxl5007t_config`, wartości ❓ jak w przykładach wyżej): `xtal_freq_hz = MxL_XTAL_24_MHZ`, `if_freq_hz = MxL_IF_4_57_MHZ`, `invert_if = 0`, `loop_thru_enable = 0`, `clk_out_enable = 1`, adres I2C `0x60` na `/dev/i2c-0` (`1f206800.miic`).
